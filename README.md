# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

```typescript
type TCategory = keyof typeof categoryMap;

interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: TCategory;
  price: number | null;
}

type TPayment = 'card' | 'cash';

type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;

interface IBuyer {
  payment: TPayment | '';
  email: string;
  phone: string;
  address: string;
}

interface IProductListResponse {
  total: number;
  items: IProduct[];
}

interface IOrderRequest extends IBuyer {
  total: number;
  items: string[];
}

interface IOrderResult {
  id: string;
  total: number;
}
```

### Модели данных

#### Класс СatalogModel
Отвечает за хранение общего списка товаров и управление товаром, выбранным для детального просмотра в модальном окне.

Конструктор
Конструктор не принимает обязательных параметров и инициализирует `items` пустым массивом, а `preview` значением `null`.

Поля класса:  
`items: IProduct[]` — массив всех доступных товаров в магазине.
`preview: IProduct | null` — товар, выбранный покупателем для подробного отображения в модальном окне (или `null`, если окно закрыто).


Методы класса: 
`setItems(items: IProduct[]): void` — сохраняет полученный массив товаров в модель.
`getItems(): IProduct[]` — возвращает текущий массив товаров из модели.
`getItem(id: string): IProduct | undefined` — находит и возвращает один товар по его уникальному `id`.
`setPreview(item: IProduct): void` — сохраняет товар для детального отображения в модальном окне.
`getPreview(): IProduct | null` — возвращает товар, выбранный для подробного отображения.

#### Класс BasketModel
Отвечает за хранение списка товаров, добавленных покупателем в корзину, и вычисление их итоговой стоимости.

Конструктор
Конструктор не принимает параметров и инициализирует поле `items` пустым массивом.

Поля класса:  
`items: IProduct[]` — массив товаров, находящихся в корзине.

Методы класса: 
`add(item: IProduct): void` — добавляет полученный товар в массив корзины.
`getItems(): IProduct[]` — возвращает массив товаров, находящихся в корзине.
`remove(id: string): void` — удаляет товар из массива корзины по его `id`.
`clear(): void` — полностью очищает корзину (очищает массив `items`).
`getTotalPrice(): number` — вычисляет и возвращает общую стоимость всех товаров в корзине.
`getCount(): number` — возвращает общее количество товаров в корзине.
`isInBasket(id: string): boolean` — проверяет наличие товара в корзине по его `id`. Возвращает `true`, если товар уже добавлен.

#### Класс BuyerModel
Отвечает за хранение персональных данных покупателя и их валидацию перед отправкой заказа.

Конструктор
Инициализирует все поля дефолтными пустыми значениями (`payment: ''`, `address: ''`, `phone: ''`, `email: ''`).

Поля класса:  
`payment: TPayment` — выбранный способ оплаты (`'card'`, `'cash'` или `''`).
`address: string` — адрес доставки.
`phone: string` — номер телефона.
`email: string` — адрес электронной почты.

Методы класса: 
`setData(data: Partial<IBuyer>): void` — сохраняет переданные данные покупателя. Принимает объект с частичными данными (Утилитарный тип `Partial<IBuyer>`), что позволяет обновить только одно или несколько полей (например, только `address`), не перезаписывая остальные.

`getData(): IBuyer` — возвращает полный объект с текущими данными покупателя.

`clear(): void` — сбрасывает все поля покупателя к исходным пустым значениям.

`validate(): TBuyerErrors` — проверяет заполнено ли каждое из полей (`payment`, `email`, `phone`, `address`). Возвращает объект, где ключи — это имена полей с ошибкой, а значения — текст ошибки (например `{payment: 'Не выбран способ оплаты'}`). Если ошибок в поле нет, соответствующий ключ в возвращаемом объекте отсутствует.

### Слой коммуникации

#### Класс WebLarekApi
Отвечает за организацию взаимодействия приложения с REST API сервера «Веб-ларёк». Использует паттерн композиция, принимая базовый класс Api для выполнения HTTP-запросов и форматирования полученных данных.

Конструктор
`api: IApi` — экземпляр класса `Api` (или объект, реализующий интерфейс `IApi`), предоставляющий методы `get` и `post`.

Поля класса:
`api: IApi` — хранит переданный экземпляр класса `Api` для выполнения запросов на сервер.

Методы класса:
`getProductList(): Promise<IProductListResponse>` — делает GET-запрос по эндпоинту `/product` и возвращает сырой ответ сервера `{ total: number, items: IProduct[] }`, если `Promise`, возвращаемый методом `getProductList()`, отклоняется `(reject)`, он безопасно перехватывается в .`catch()`, не ломая работу всего JS-приложения.

`orderProducts(order: IOrderRequest): Promise<IOrderResult>` — отправляет составной объект заказа (данные покупателя, итоговую сумму и массив ID купленных товаров) методом `POST` на эндпоинт `/order`. Возвращает ответ сервера с созданным `id` заказа и списанной суммой `total`, если `Promise`, возвращаемый методом `orderProducts(order: IOrderRequest)`, отклоняется `(reject)`, он безопасно перехватывается в .`catch()`, не ломая работу всего JS-приложения.

### Слой представления (View)

#### Абстрактный класс Component
Базовый абстрактный класс для реализации компонентов интерфейса (View) в паттерне MVP. Служит основой для всех элементов пользовательского интерфейса, предоставляя удобный инструментарий для управления DOM-элементами, внедрения данных и рендеринга.

Конструктор
`container: HTMLElement` — корневой DOM-элемент компонента, с которым будет связана вся внутренняя разметка и дочерние элементы. (Важно: код в конструкторе исполняется до всех объявлений в дочернем классе).

Поля класса:
`container: HTMLElement (protected readonly)` — хранит ссылку на корневой HTML-элемент компонента.

Методы класса:
`setImage(element: HTMLImageElement, src: string, alt?: string): void (protected)` — вспомогательный метод для безопасной установки изображения. Принимает элемент изображения, путь к источнику (src) и опциональный альтернативный текст (alt), после чего обновляет соответствующие атрибуты, если переданный элемент существует.

`render(data?: Partial<T>): HTMLElement` — универсальный метод для обновления и возврата корневого DOM-элемента компонента. Принимает объект с частичными данными (data), с помощью `Object.assign` автоматически обновляет свойства экземпляра класса и возвращает актуальный `this.container` для дальнейшей отрисовки на странице.

#### Класс Header
Отвечает за отображение шапки сайта, включая кнопку корзины и счетчик добавленных в нее товаров. Наследуется от базового класса `Component<IHeaderData>`.

Конструктор
`container: HTMLElement` — корневой DOM-элемент карточки.
`events: IEvents` - экземпляр брокера событий.

Поля класса:
`basketButton: HTMLButtonElement` — кнопка открытия корзины.
`counterElement: HTMLElement` — элемент, отображающий текущее количество товаров в корзине.
`events: IEvents` — защищённое поле для доступа к брокеру событий (передаётся через конструктор).

Методы класса:
`set counter(value: number)` — сеттер для обновления числового значения счетчика товаров на кнопке корзины.

#### Класс Gallery
Отвечает за отображение главной сетки каталога товаров на странице. Наследуется от базового класса `Component<IGalleryData>`.

Конструктор
`container: HTMLElement` — корневой DOM-элемент карточки.

Поля класса:
Класс не объявляет собственных дополнительных полей и использует корневой контейнер (`this.container`), унаследованный от базового класса `Component`.

Методы класса:
`set catalog(items: HTMLElement[])` — сеттер для вывода массива готовых HTML-элементов карточек товаров в область каталога (полностью заменяет содержимое контейнера с помощью `replaceChildren`).

#### Класс Modal
Отвечает за отображение универсального модального окна, которое управляет показом и скрытием всплывающих окон, а также содержит слот для динамической вставки различного контента (превью товара, корзина, формы, окно успешного заказа). Наследуется от базового класса `Component<IModalData>`.

Конструктор
`container: HTMLElement` — корневой DOM-элемент модального окна (`#modal-container`).
`events: IEvents` — брокер событий для обработки действий открытия/закрытия модального окна.

Поля класса:
`closeButton: HTMLButtonElement` — кнопка закрытия модального окна («крестик»).
`contentElement: HTMLElement` — контейнер (`.modal__content`), в который динамически помещается разметка активного компонента.
`windowElement: HTMLElement` — внутренний контейнер модального окна (`.modal__container`).

Методы класса:
`open(): void` — открывает модальное окно (добавляет визуальный класс активности и блокирует прокрутку страницы).
`close(): void` — закрывает модальное окно, очищает внутренний контент и снимает блокировку прокрутки.
`set content(value: HTMLElement)` — устанавливает или заменяет HTML-содержимое модального окна.
`render(data: IModalData): HTMLElement` — расширяет базовый метод рендеринга: заполняет модальное окно контентом, открывает его и возвращает готовый корневой DOM-элемент.

#### Абстрактный класс Card
Базовый абстрактный класс для управления карточками товаров (наследуется от `Component<ICard & T>`). Отвечает за инициализацию общих элементов разметки карточки и предоставление базовых сеттеров для заполнения её основных данных (название, цена, категория, изображение).

Конструктор
`container: HTMLElement` — корневой DOM-элемент карточки.

Поля класса:
`titleElement: HTMLElement` — элемент отображения заголовка товара.
`priceElement: HTMLElement` — элемент отображения цены товара.

Методы класса:
`set title(value: string)` — устанавливает текстовое название товара.
`set price(value: number | null)` — сеттер для установки стоимости товара (если значение равно `null`, выводит текст «Бесценно», иначе отображает число с суффиксом «синапсов»).

#### Класс CardCatalog
Отвечает за отображение карточки товара в блоке каталога на главной странице (шаблон `#card-catalog`). Наследуется от базового класса `Card<ICardCatalog>`.

Конструктор
`container: HTMLElement` — корневой DOM-элемент карточки каталога (кнопка).
`actions?: { onClick: (event: MouseEvent) => void }` — опциональный объект с колбэками для обработки клика по карточке.

Поля класса:
`categoryElement: HTMLElement` — элемент отображения категории товара.
`imageElement: HTMLElement` — элемент отображения изображения товара.

Методы класса:
`set category(value: string)` — сеттер для установки категории товара (обновляет текст и применяет соответствующий стилевой модификатор на основе `categoryMap`).
`set image(value: { src: string; alt: string })` — сеттер для установки изображения товара и его альтернативного текста с помощью встроенного метода `setImage`.

#### Класс CardPreview
Отвечает за отображение детальной информации о товаре в модальном окне (шаблон `#card-preview`). Наследуется от базового класса `Card<ICardPreview>`.

Конструктор
`container: HTMLElement` — корневой DOM-элемент расширенной карточки.
`actions?: { onClick: (event: MouseEvent) => void }` — колбэк для обработки клика по кнопке добавления товара в корзину.

Поля класса:
`categoryElement: HTMLElement` — элемент отображения категории товара (`.card__category`).
`imageElement: HTMLImageElement` — элемент отображения изображения товара (`.card__image`).
`textElement: HTMLElement` — элемент отображения подробного описания товара (`.card__text`).
`buttonElement: HTMLButtonElement` — кнопка действия для добавления товара в корзину или удаления из неё (`.card__button`).
`events: IEvents` — защищённое поле для доступа к брокеру событий (передаётся через конструктор).

Методы класса:
`set category(value: string)` — сеттер для установки категории товара (обновляет текст и применяет стилевой модификатор на основе categoryMap).
`set image(value: { src: string; alt: string })` — сеттер для установки изображения товара и его альтернативного текста.
`set description(value: string)` — сеттер для установки текста детального описания товара.
`set buttonText(value: string)` — сеттер для изменения текста на кнопке действия (например, «Купить» / «Удалить из корзины» / «Недоступно»).
`set buttonDisabled(value: boolean)` — сеттер для блокировки или разблокировки кнопки покупки.

#### Класс CardBasket
Отвечает за отображение товара в списке мини-корзины (шаблон `#card-basket`). Наследуется от базового класса `Card<ICard>`.

Конструктор
`container: HTMLElement` — корневой DOM-элемент элемента списка корзины.
`actions?: { onDelete: (event: MouseEvent) => void }` — колбэк для обработки клика по кнопке удаления товара из корзины.

Поля класса:
`indexElement: HTMLElement` — элемент отображения порядкового номера товара в списке.
`deleteButton: HTMLButtonElement` — кнопка удаления товара из корзины.

Методы класса:
`set index(value: number)` — устанавливает порядковый номер строки товара в корзине.

#### Абстрактный класс Form
Базовый абстрактный класс для управления интерактивными формами (наследуется от `Component<T & IFormState>`). Отвечает за общую логику работы с полями ввода, автоматическую генерацию событий при изменении инпутов, обработку событий отправки и отображение ошибок валидации.

Конструктор
`container: HTMLFormElement` — корневой DOM-элемент формы.
`events: IEvents` — брокер событий для передачи данных о вводе и сабмите в презентер.

Поля класса:
`submitButton: HTMLButtonElement` — кнопка отправки формы (`button[type=submit]`).
`errorsElement: HTMLElement` — элемент для отображения текста ошибок валидации (`.form__errors`).
`events: IEvents` — защищённое поле для доступа к брокеру событий.

Методы класса:
`protected onInputChange(field: keyof T, value: string): void` — защищенный метод, генерирующий событие изменения конкретного поля с динамическим именем (на основе имени формы и ключа поля).
`set valid(value: boolean)` — сеттер для управления состоянием доступности кнопки отправки (активирует или блокирует её в зависимости от валидности формы).
`set errors(value: string | string[])` — сеттер для вывода текста ошибок валидации (поддерживает как единую строку, так и массив строк, объединяя их через разделитель).

#### Класс OrderForm
Отвечает за отображение и управление первой частью формы оформления заказа: выбор способа оплаты и ввод адреса доставки (шаблон `#order`). Наследуется от базового класса `Form<IOrderForm>`.

Конструктор

`events: IEvents` — брокер событий.

Поля класса:
`paymentButtons: HTMLButtonElement[]` — коллекция кнопок выбора способа оплаты (`.button_alt`).
`addressInput: HTMLInputElement` — поле ввода адреса доставки (`[name=address]`).

Методы класса:
`set payment(value: string)` — сеттер для подсветки выбранного способа оплаты (устанавливает активный класс `button_alt-active` для соответствующей кнопки по её имени).
`set address(value: string)` — сеттер для установки значения в поле ввода адреса.

#### Класс ContactsForm
Отвечает за отображение и управление второй частью формы оформления заказа: ввод контактных данных пользователя — email и телефона (шаблон `#contacts`). Наследуется от базового класса `Form<IContactsForm>`.

#### Класс Basket
Отвечает за отображение модального окна корзины, содержащего список выбранных товаров, общую стоимость и кнопку перехода к оформлению заказа (шаблон `#basket`). Композиционно включает в себя элементы класса `CardBasket` для каждого товара в списке. Наследуется от базового класса `Component<IBasketView>`.

Конструктор

Поля класса:

### Раздел: События приложения (Event Bus & Callbacks)

В данном разделе собраны все события, которые генерируются компонентами представления (View) и передаются в презентер через брокер событий (IEvents) или колбэки, полученные в конструкторе.

#### События каталога и карточек (`Card`, `CardCatalog`, `CardPreview`)
`card:select`
Где генерируется: `CardCatalog` (при клике на карточку товара в списке).
Описание: Уведомляет презентер о том, что пользователь выбрал конкретный товар для просмотра детальной информации (открытия модального окна предпросмотра).

`card:action`
Где генерируется: `CardPreview` (при клике на кнопку действия внутри модального окна предпросмотра).
Описание: Инициирует добавление товара в корзину или его удаление (в зависимости от текущего статуса товара).

#### События корзины (`Basket`)
`basket:open`
Где генерируется: Главный компонент шапки страницы / кнопка корзины.
Описание: Запрос на открытие модального окна корзины.

`order:open`
Где генерируется: `Basket` (при клике на кнопку «Оформить»).
Описание: Сигнализирует о переходе из корзины к первому шагу оформления заказа (форма с выбором оплаты и адреса).

`basket:remove`
Где генерируется: `CardBasket` (при клике на иконку удаления товара из корзины).
Описание: Запрос на удаление конкретного товара из корзины.

#### События форм оформления заказа (`Form`, `OrderForm`, `ContactsForm`)
`order.field:change` / `contacts.field:change` (или динамические ключи по имени поля)
Где генерируется: `Form` (при вводе данных в любой инпут через метод `onInputChange`).
Описание: Уведомляет модель об изменении значения конкретного поля ввода (`payment`, `address`, `email`, `phone`) для запуска валидации.

`order:submit`
Где генерируется: `OrderForm` (при отправке первой части формы).
Описание: Сигнализирует о подтверждении способа оплаты и адреса, запуская переход ко второму шагу (контакты).

`contacts:submit`
Где генерируется: `ContactsForm` (при сабмите финальной формы).
Описание: Сигнализирует о завершении ввода контактов и готовности отправить данные заказа на сервер.

#### Событие завершения покупки (Success)
`success:close` (или через колбэк `onClick`)
Где генерируется: `Success` (при клике на кнопку «За новыми покупками!»).
Описание: Закрывает модальное окно успешного заказа, очищает корзину и возвращает пользователя на главную страницу каталога.

### Слой диспетчера (Presenter)

#### Класс Presenter
Главный исполняемый файл приложения, реализующий архитектурный паттерн MVP с событийно-ориентированным подходом (Event-Driven Architecture). Выступает в роли центрального слоя оркестрации, который связывает модели данных (`CatalogModel`, `BasketModel`, `BuyerModel`) и компоненты пользовательского интерфейса (View) через брокер событий (`EventEmitter`).

##### Основные задачи модуля:
Инициализация брокера событий, базового API и клиента `WebLarekApi`.
Создание экземпляров моделей данных и статических/динамических компонентов представления (View).
Регистрация централизованных обработчиков событий для управления жизненным циклом каталога, корзины, интерактивных форм и модальных окон.
Загрузка начальных данных с сервера и запуск приложения.

##### Инициализируемые компоненты и зависимости:
`events: EventEmitter` — глобальный брокер событий для межкомпонентного взаимодействия.
`api: WebLarekApi` — специализированный сервис для выполнения запросов к серверному API.

Модели: `catalogModel` (каталог товаров), `basketModel` (корзина покупок), `buyerModel` (данные покупателя и состояние чекаута).

Представления: 
`gallery` (главная сетка каталога), 
`header` (шапка сайта со счетчиком), 
`modal` (универсальный контейнер модальных окон), 
`basketView` (модальное окно корзины), 
`cardPreview` (превью карточки товара), 
`orderForm` (первая часть формы заказа — оплата и адрес), 
`contactsForm` (вторая часть формы заказа — контакты), 
`successView` (окно успешного завершения покупки).

##### Регистрируемые обработчики событий (events.on):
Управление каталогом и превью (`catalog:changed`, `card:select`, `preview:changed`, `card:action`):
Перерисовывает карточки в галерее при обновлении списка товаров.
Обрабатывает выбор карточки пользователем, сохраняет её в качестве превью в модели и открывает модальное окно с подробной информацией (`CardPreview`).
Управляет динамическим состоянием кнопки предпро («Купить», «Удалить из корзины» или «Недоступно» для товаров без цены).
Обрабатывает действия добавления или удаления товара из корзины при клике в модальном окне.

##### Управление корзиной (basket:changed, basket:open, basket-item:remove):
Обновляет счетчик товаров в шапке сайта (`Header`) и перерисовывает содержимое корзины с пересчетом общей суммы.
Открывает модальное окно корзины по запросу пользователя.
Удаляет выбранный товар из корзины по клику на иконку удаления в элементе `CardBasket`.

##### Управление оформлением заказа и формами (order:open, поля ввода, buyer:changed, order:submit, contacts:submit, success:close):
Открывает первую форму заказа (`OrderForm`), подтягивая сохраненные данные и актуальные ошибки валидации.
Синхронизирует ввод данных в полях инпутов с моделью покупателя (`BuyerModel`) и запускает валидацию.
Динамически обновляет состояние валидности (`valid`) и текста ошибок (`errors`) для обеих форм заказа.
Обрабатывает отправку первой формы (`order:submit`) и переключает интерфейс на форму контактов (`ContactsForm`).

Выполняет финальную отправку заказа на сервер (`api.orderProducts`), открывает окно успешного оформления (`Success`), очищает модели корзины и покупателя, а также закрывает модальные окна по завершении сценария.

##### Стартовая инициализация:
Перед загрузкой данных очищаются модели корзины и покупателя, после чего выполняется запрос на получение списка товаров (`api.getProductList()`), пути к изображениям дополняются префиксом CDN, и каталог передается в модель для отрисовки интерфейса.
